# Keeping step with Emmett

Much of this library's read side, its testing specs and its Express adapter were adapted from
[Emmett](https://github.com/event-driven-io/emmett) (MIT, see `NOTICE`). They were adapted, not forked: our files have
other names and shapes, and a DCB (tag and boundary) model instead of streams. So Emmett can't be merged in. Each
Emmett pull request that touches what we adapted is **read, judged and, when worth it, ported by intent**: its tests
translated first, then the change.

This file is the record. `pnpm upstream:emmett` reads it: the baseline, the paths watched, the file map and the
review log below.

## The routine

1. **When:** at the start of every library phase, before a release, or when someone points at an Emmett PR.
2. `pnpm upstream:emmett` lists the Emmett PRs merged since the baseline that touch a watched path and aren't in
   the review log yet, each with the files of ours it maps to. `pnpm upstream:emmett --fetch` also fast-forwards the
   reference clone (`../emmett`, or `EMMETT_DIR`) for reading the diffs locally. `--check` exits 1 while any are
   untriaged.
3. **Triage each one into the review log**, with a verdict:
    - **take:** port it. Branch `upstream/emmett-<pr>` (or a commit in the current phase), Emmett's tests translated
      first, then the change; the commit is `upstream: emmett#<pr> <title>`; a `NOTICE` entry if new code is adapted.
    - **pattern:** the change doesn't apply as code, but its lesson does. Name what it found in ours.
    - **later:** worth having, not now. Say when.
    - **n/a:** doesn't touch anything we adapted. One line is enough.
4. **Move the baseline** to Emmett's `main` once every PR merged before it is in the log.

A PR touching none of the watched paths is reported as a count, not listed. Log it as n/a anyway when its title
suggests a behaviour we copied.
